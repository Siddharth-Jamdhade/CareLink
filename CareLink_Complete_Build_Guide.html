from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, declarative_base
from .config import DATABASE_URL

engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)
Base = declarative_base()

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

File: backend/app/models.py

This defines your database tables — think of each class as a spreadsheet:

TableWhat It StoresKey Columns

🔑 Key concept — the status field on extracted_facts has 4 possible values:
• "verified" — Confirmed by a human ✅
• "unverified" — Extracted by AI, awaiting confirmation 🟡
• "conflict" — Disagrees with another record 🔴
• "missing" — Expected by protocol but no record found ⚪

Build the OCR Service

What is OCR? Optical Character Recognition — it reads text from images. Think of it as the AI's "eyes" for printed text.

File: backend/app/services/ocr_service.py

What this file does:

  • Takes an image file path (e.g., uploads/anc_card.jpg)
  • Runs PaddleOCR to detect all text in the image
  • Returns all detected text as one combined string

How to build it:

from paddleocr import PaddleOCR

# Initialize ONCE at startup (takes 2-3 sec to load models)
ocr = PaddleOCR(use_angle_cls=True, lang='en')

def extract_text(image_path: str) -> str:
    result = ocr.ocr(image_path, cls=True)
    # result is a list of lists of [box, (text, confidence)]
    lines = []
    for page in result:
        if page:
            for line in page:
                text = line[1][0]  # the detected text
                lines.append(text)
    return "\n".join(lines)
💡 First run is slow (~30 sec) because PaddleOCR downloads model files. After that, each image takes 1–3 seconds.

Build the AI Extraction Service (Most Important File)

What this does: Takes the OCR text + original image → sends both to Gemini AI → gets structured JSON with visit dates, facility names, document types, etc.

File: backend/app/services/llm_extractor.py

How to build it:

  • Import the Gemini SDK: from google import genai
  • Create a client: client = genai.Client(api_key=GEMINI_API_KEY)
  • Load the image as bytes using PIL.Image
  • Send a multimodal prompt (text + image) to gemini-2.0-flash
  • Parse the JSON response
  • Calculate confidence scores

The Extraction Prompt (use this exactly)

"""
You are a medical record data entry assistant. You extract
ONLY administrative facts from maternal health records.
You NEVER interpret clinical data, diagnose, score risk,
or recommend treatment.

Extract these fields into JSON:

{
  "visit_date": "YYYY-MM-DD or null if unclear",
  "facility_name": "string or null",
  "document_type": "ANC Card | Prescription | Lab Report |
      Ultrasound | Referral Note | Vaccination Record |
      Discharge Summary | Other",
  "gestational_week": integer or null,
  "pending_items": ["list of follow-ups or tests mentioned"],
  "provider_name": "doctor/nurse name or null",
  "next_appointment": "YYYY-MM-DD or null",
  "confidence_notes": "anything unclear and why"
}

Rules:
- Only extract what is clearly written. Do not infer.
- If unclear, set to null and explain in confidence_notes.
- Do NOT extract vitals, BP, weight, or lab values.
- Return ONLY valid JSON. No extra text.

OCR Text from this document:
{ocr_text}
"""

Confidence Scoring Logic

ConditionConfidence Score
Field returned by Gemini AND confirmed by OCR text0.85 – 0.95
Field returned by Gemini but OCR text is ambiguous0.60 – 0.80
Field mentioned in confidence_notes as unclear0.40 – 0.55
Field is null / not found0.0

Auto-set status:

  • Confidence ≥ 0.80 → status = "unverified" (good but needs human OK)
  • Confidence < 0.80 → status = "unverified" + flag for priority review
  • Nothing starts as "verified" — only a human can set that

Build the Conflict Detector

File: backend/app/services/conflict_detector.py

When to run: Every time a new fact is extracted for a patient.

What it does: Compares the new fact against all existing facts for that patient. If any rules trigger, it marks both facts as "conflict".

Implement these 5 conflict rules:

#Rule NameLogicExample
1Date collisionTwo records show visits within 2 days but at different facilitiesRecord A: "PHC, 12 Aug" vs Record B: "Sub-centre, 13 Aug"
2Gestational week mismatchIf Visit A says 20 weeks on Aug 12, Visit B says 18 weeks on Sep 9 — that's impossible (weeks should increase)Week goes backward between visits
3Duplicate documentSame document_type + same facility + dates within 3 daysTwo "ANC Card" entries from same PHC, 1 day apart
4Contradictory itemsAn item listed as "done" in one record but "pending" in a later recordTT-1 "given" in Record A, TT-1 "pending" in Record B (later date)
5Missing linkVisit 1 and Visit 3 exist but no Visit 2Gap in the sequence

How to implement: Write a function detect_conflicts(patient_id, new_fact, all_existing_facts) that loops through each rule and returns a list of conflicts found.

Write Patient Data to NFC Wristband

What we store on the wristband: A short URL like https://carelink.app/p/P-0417

When any phone taps the wristband, it reads this URL and opens the CareLink PWA at that patient's journey page.

How to write to NTAG215:

  • Format the URL as an NDEF URI record (this is the standard NFC data format)
  • Use the MFRC522 library's MIFARE_Write() function to write data blocks
  • NTAG215 has pages 4–129 available for user data (504 bytes — plenty for a URL)
💡 For the demo, the simplest approach:
Write the wristband BEFORE the demo using the ESP32. On stage, just tap your phone on it — modern Android and iOS phones have built-in NFC readers that automatically open URLs from NFC tags. No app needed on the phone.

Build the QR Code Generator

Backend endpoint: GET /api/patients/{id}/qr

import qrcode
import io
from fastapi.responses import StreamingResponse

@router.get("/{patient_id}/qr")
def get_qr(patient_id: str):
    url = f"https://carelink.app/patient/{patient_id}"
    img = qrcode.make(url)
    buf = io.BytesIO()
    img.save(buf, format="PNG")
    buf.seek(0)
    return StreamingResponse(buf, media_type="image/png")

Add Voice Verification

What: Health worker asks the mother a question. Her spoken answer is matched against the extracted data.

Frontend — use the browser's Web Speech API:

const startVoiceVerification = (factId) => {
  const recognition = new (window.SpeechRecognition
    || window.webkitSpeechRecognition)();
  recognition.lang = 'en-IN';  // Indian English
  recognition.start();

  recognition.onresult = async (event) => {
    const transcript = event.results[0][0].transcript;
    // Send to backend for matching
    await API.post(`/verify/${factId}/voice`, {
      spoken_text: transcript
    });
  };
};

Backend — fuzzy matching:

  • Receive the spoken text: "September ninth at the sub-centre"
  • Compare against the extracted visit_date: "2026-09-09" → convert both to comparable format
  • Check for date words: "September" → 09, "ninth" → 09
  • Check facility: "sub-centre" matches "Sub-centre Wardha"
  • If match → add "patient_voice" to verified_by, boost confidence by 0.10
  • If mismatch → create a new conflict entry
💡 For the demo: If Web Speech API is flaky, pre-record a voice clip and play it. Show the transcript appear, then show it matching. The concept matters more than perfect speech recognition.

File: backend/app/services/protocol_checker.py

Logic:

  • Load the protocol JSON

  •   → Check if a matching visit record exists
